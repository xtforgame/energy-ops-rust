# 電號主表與租金來源核對

電號、案場名稱、持有公司以電費主表為準。租金規則與地主來源按案場連接，租約完整度獨立保存。

## 本輪修正

- 地主表不再只憑專案編號相同就配對；改以案場名／已載別名核對，保留編號差異與收款人互證。
- 空白地主列仍保留來源證據，不沿用上一案的地主和租金。
- 共用年額以整組參考呈現，個別案場應付金額保持空白，群組識別與成員可查。不將整組金額重複列入每個案場付款。
- 年額已知、分期算法未知時，顯示年額；只有明示全年試算才計算全年，不能擅自平均拆分。
- 同案場多個收款對象可顯示各自年付／月付歷史參考，未知月付公式不以歷史實付金額代替。
- 固定與面積型租金不產生沒有意義的單筆收入比例貢獻列。
- 每期固定額的試算月份須與原付款週期一致，不能把一季金額誤標成半年金額。
- 客戶 2026-11-25 確認資產表 H 欄「業主自建案」不用付租金。來源解析保留此分類，平台顯示不適用，不產生零元付款，也不影響電費作業。

## 新補充的業務規則

- 同案場以一張 EF 單申請；多位個人地主明細保留在同案場，不能因多個名字拆成多張申請。本輪未變更 EF 送件或多收款人填表程式。
- 個人地主不開發票，不能單以沒有發票判定缺件；其他應附租金計算、合約或收據仍按案件需求。
- 多數電費單每月寄，少數每兩個月寄。季付／半年付以單據涵蓋期間完整與否判斷，不以固定張數判斷。本輪沒有新增完整期段拼接演算法。

本機資產表有 9 列自建案，不在原 32 筆核對範圍；其中 4 列有完整電號但未匹配電費主表及本地案場，5 列沒有完整電號。大表保留免租分類，未擅自新增案場或跨案配對。

## 資料更新方式

私有來源資料包不納入程式庫。使用 `scripts/data-import/refresh-rent-rules.mjs` 更新既有規則；先 dry run，再 `--apply`。以電號唯一定位案場、sourceKey 定位規則，核對版本與來源雜湊；附件 ID 僅能用於相同安裝環境。跨環境必須重新對應附件，不能照搬 ID。

本輪本地已更新 32 筆，重跑為 32 筆 unchanged，不新增規則。電費主表與大表的電號、名稱、公司逐筆相符。保留更新前資料庫備份與更新差異。既有歷史租金預覽未重寫。

## 驗證邊界

來源解析測試、租金 domain 測試、相關 UI 測試、TypeScript 檢查與 build 通過。本地 API 驗證固定額、整組額及未知分期；瀏覽器驗證四種顯示。Excel 逐筆核對 32 筆並掃描公式錯誤。

已知條件可預覽，不代表已核准付款。個案尚缺的適用日期、週期起點、取整、稅務或級距條款仍按欄位列出。沒有部署客戶遠端、沒有執行 EasyFlow 送件，也沒有宣稱所有案場下一期皆能自動結算。
