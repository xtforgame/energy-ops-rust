# 正式上線缺口修正與驗收

目標：依 2026-11-24 本地實測失敗逐項修復，原始單據可產生可追溯、可審核的電費與租金申請。未確認規則不臆測，客戶環境不更新，EF 不實送。

架構：沿用 Rust 平台、PostgreSQL、MinIO 與獨立 OCR 服務；合併已有來源辨識，將流程、附件、租金草稿持久化串接。客戶原件與測試憑證不入 Git。

技術：Rust / Actix / SQLx、React / TypeScript、Docker、本地 Playwright。

## 修正順序

- [ ] 保留既有租金修改，整合 Rick 三家購電單據分支。
- [ ] 修一般審核員直接操作失敗；驗任一人通過、競爭與組外拒絕。
- [ ] 修附件簽名公開端點；驗上傳、下載與隔離。
- [ ] 修多頁 PDF 限制與錯誤分類，重跑三家原檔及小港原檔。
- [ ] 串正式租金資料與來源、週期彙總、缺件檢查，驗三案金額。
- [ ] 保存憑證先附／後補狀態，補申請必要欄位檢查與附件交接。
- [ ] 核對三組審核、報表、紀錄、提醒、重試與備份等其餘本地可行項。
- [ ] 重新測試 UI / API / 原始資料，產出可跑通與外部阻擋清單。

## 驗收原則

測試分通過、失敗、未驗與待客戶確認。手工整理輸入計算成功不等於 PDF 自動匯入成功。單一展示不代表正式容量或客戶環境驗收。級距邊界、蘇澳計價基準與未確認期限保持待確認。
