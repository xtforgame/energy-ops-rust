## API 與狀態

- `GET /api/v1/orgs/{org}/energy/bills/{id}/easyflow-application`：依目前單據與主檔產生表單，回傳 `sourceRevision`、`canReview`、`applicationReview`。
- 同路徑 `POST`：`{sourceRevision, draftRevision, action: "save" | "confirm", values: {...}}`。兩種版本都需沿用 GET 最新回應，避免舊分頁覆寫他人已存草稿。
- 僅接受申請人、部門、公司代碼、日期、摘要及申請選項；不接受從表單任意覆寫辨識金額、案場或電號。這些資料應透過既有校對／主檔功能修正。
- 採組織權限、既有單據編輯模式及交易內稽核；資料保存在 `bill.data.easyflowApplication`，不需新增資料庫 migration。
- 來源版本不符回 409；重新讀取顯示 `needs_recheck`。原單／主檔變動不能沿用舊確認。
- `confirmed_for_handoff` 只代表內容準備確認；**不改工作流 approvalState，不送 EF，不建立付款**。`submissionAllowed` 仍為 false。

## 邊界及後續

- 缺來源的公司代碼、申請人、部門、日期與正式選項留待設定或補齊，不套用其他案場範例。
- 兩份逆變器樣本已有正確付款總額，但細項尚未完全對平；表單保留提醒，不宣稱所有費用拆分已完成。
- 表單的內容確認與既有簽核流程分開。既有送審流程仍有租約／規則的限制，本次沒有修改那套流程，也沒有驗收 EF 實際送件。
