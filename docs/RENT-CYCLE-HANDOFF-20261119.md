# 地主租金週期試算 — 2026-11-19 交接

## 本次交付

延續 `codex/easyflow-application-export` 分支，新增案場詳情「合約時間軸」的 **租金週期試算**。
不必先填地主租約，仍可使用前一版電費單的「準備 EasyFlow 申請資料」。本次沒有修改既有工作流關卡，也沒有替客戶確認電費開票與地主租金的依賴關係。

已實作：

- 固定租金：面積 × 單價；明確指定單價為每月或每個付款週期，月單價乘週期月數。
- 比例租金：所選週期台電與轉供的收入基底合計 × 比例。含稅／未稅由合約設定明確選擇，不以扣除電表租費後的應付淨額代替。
- 每 1～12 個月一期、明確的第一期起日與本次計算起日、四捨五入至整元／1 位／2 位。
- 有轉供時，台電與轉供都必須覆蓋完整週期。0 元有效；沒有單據、缺金額、缺度數均不當成 0。
- 結果固定保留兩種來源的收件狀態、收入與度數；未轉供的轉供欄為「不適用」。
- 期間缺漏、重疊、跨期、重複單據、未知來源均列出原因，不偷偷分攤或加總。
- 合約設定儲存並記錄稽核；載入資料庫中同組織、同案場的候選單據；日期從資料庫取得，前端不可任意偽造。
- 可查看原始附件、確認來源與收入／度數後試算，匯出 JSON（含規則快照、單據快照、來源附件、待確認事項）。修改輸入後舊結果失效。

## 如何操作

1. 案場必須先關聯地主合約，效期涵蓋待算的完整週期。
2. 案場詳情 → 合約時間軸 →「租金週期試算」。
3. 設定起日、付款週期、是否轉供、算法、比例或面積單價及含／未稅基底。
4. 按「儲存試算設定並載入單據」。
5. 勾選本期收入單據。已辨識的台電購電電費、電費合計、購電度數會帶入；來源不明保持待確認，不推測轉供。
6. 核對／補入數值後試算；缺件會明列。這些修改僅為試算輸入，不覆寫原始 OCR。
7. 匯出 JSON 給後續流程或拿來與客戶的實際租金範例核對。

4. 切換正式流程時，必須停用該租約舊的逐單觸發，避免同一期間重複建立租金；用合約＋案場＋週期＋版本設正式付款唯一鍵。**此分支未自動切換既有流程**。
5. 週期中的轉供切換、多電號同期間、跨月邊界／不完整月份、一份租約跨多案場，以及年度／跨年稅務，需以實際規則擴充。本版不猜測：僅支援月初起算、完整月份，重疊與跨期會阻擋試算；每份合約目前只儲存一個案場的試算設定，不允許直接覆蓋成另一案場。

## API 與資料

以下前綴皆為 `/api/v1/orgs/{orgId}/energy`：

|方法|路徑|權限／用途|
|---|---|---|
|GET|`/contracts/{contractId}/rent-cycle`|FLOW_VIEW；讀設定，沒有設定回 plan=null|
|POST|`/contracts/{contractId}/rent-cycle`|MASTER_MANAGE；儲存 Plan，寫 contract.updated 稽核|
|GET|`/contracts/{contractId}/rent-cycle/bills?start=YYYY-MM-DD`|FLOW_VIEW；同案場重疊帳期及缺日期候選單據；最多 500 張，超出報錯|
|POST|`/contracts/{contractId}/rent-cycle/preview`|FLOW_VIEW；使用已儲存設定試算，無付款／流程寫入|

設定存在 `tbl_energy_contract.data.rentCycleDraft`，使用既有 JSONB，不需新增 migration。設定帶 stationId、anchor、months、transfer、kind（fixedArea/revenueShare）、basis（untaxed/gross）、sharePercent、area、unitPrice、unitPeriod（month/cycle）、roundingPlaces。

試算 request：`{"start":"2026-07-01","receipts":[{"billId":123,"source":"taipower","untaxed":"1000","gross":"1050","kwh":"300"}]}`。
所有數值使用十進位字串，未知為 null。API 驗證單據歸屬與資料庫期間；來源與金額是使用者確認的草稿輸入，結果明載 `inputProvenance`。不得把它解讀成已完成 OCR／人工審批的證明。

結果固定 `state=draft`、`taxStatus=pendingConfirmation`、`paymentAllowed=false`、`netPayable=null`。`baseRent` 只有資料檢查通過才有值，**不是可匯款金額**。不建立 payout_record、不改審核狀態、不發信、不送 EasyFlow。
