# 案場、租金規則與租約佐證分離

案場主檔以既有電號對應為基礎，新增可重用租金規則及獨立的租約備件狀態。規則不是完整租約的替代品；缺完整租約不再直接等同不能試算。

## 實作

- migration 0111：規則與版本歷史，關聯組織及案場。
- 案場 API：讀取、建立及修改規則；管理權限、附件組織檢查、版本衝突及效期重疊檢查、異動紀錄。
- 案場畫面：規則條件、來源原值、備註、已確認／待確認、租約尚缺／摘錄／完整附件。
- 租金預覽：按有效規則及週期彙整已配對電費資料。使用售電收入欄位，不能以扣除電表租費後的應付總額代替。
- 歷史人工草稿保留，與自動週期重疊時不混算。不同入口使用同一防重複判斷。
- 匯入工具：唯一電號定位案場，相同來源保留既有規則；真實資料包不進 Git。附件 ID 不可跨環境直接沿用。

## 驗證

- Rust domain 153 項通過；隔離 HTTP 整合測試通過，涵蓋權限、版本、缺件及自動計算。
- 前端 10 項聚焦測試及 production build 通過。
- 資料準備工具 3 項測試通過。
- 本地 API 匯入後讀回，重跑匯入新增 0 筆，既有規則均保留。
- 合成下一期台電及轉供收入，驗證逐筆比例取整、稅額與總額；缺任一必要來源不給可付款金額，零元來源仍需存在。
- 原始歷史驗算記錄仍存在，金額未變。完整租約未備齊不阻擋規則試算。

## 界線

目前可啟用的自動規則是比例型，週期 1–12 個月、起算日 1–28 日。固定金額、最低保證或級距等條件可以保留，但此新增機制尚未把它們宣告為已支援的自動規則。已驗算的歷史草稿照舊可查看。

自動預覽從資料庫當下已辨識、已配對的單據計算，不代表已核准、已付款，也沒有自動送出 EasyFlow。合成下一期測試證明接線與計算，不能當作下一期真實 PDF 已通過 OCR。

本次僅更新本地測試平台；未更新客戶遠端。實際案場筆數、附件及結果詳見私有 `output/rent-rules-20261125`。
