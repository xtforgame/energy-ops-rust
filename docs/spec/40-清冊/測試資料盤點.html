測試資料盤點

驗收要能判定合格，每一項都需要測試資料與標準答案。這一頁盤點每類測試資料現在有沒有、在哪裡（包含各 repo 的 branch），沒有的都轉成第四批問題向雲豹索取。

案場與地主的資料有了嗎？

案場：有名單，還沒進系統。使用者提供的「1.發電案場清單」有 98 個真實案場（11 家子公司、16 個區處、電號、容量、發票寄送方式）；系統內與各 branch 只有同一套示範種子的 6 個虛構案場，其中 4 個電號與真實案場相同。名單缺專案編號、型別、併網日、案場分類與合約關聯（TD-01、Q-36）。

地主：沒有。資產管理清單的地主頁只有表頭與一列「我是範例」；原版、App 5、energy-ops-next、energy-ops-rust 的示範種子都是同兩位虛構地主（含假身分證字號與銀行帳號）。多地主比例、繼承異動、公司或機關受款人都沒有資料（TD-02、Q-37）。

搜尋範圍（2026-11-12）

az repo 全部 branch 與歷史（含 feat-energy-ops-next、feat-tenant-console-route-transition、archive 與 backup 分支）、App 5 的全部 branch、energy-ops-rust（master、rust-port）、辨識服務的 samples 與 fixtures、az repo 的 temp 與本機上傳區。除了使用者這次提供的附件，找到的案場與地主資料都是示範種子；沒有任何真實地主名冊、合約檔、天能電費單或發票檔。

建議做法：與雲豹約定一個「驗收基準月」（Q-45），由雲豹提供該月全部輸入與人工結果，同一批資料同時當作開發測試資料與驗收的標準答案。含個資的資料可以先去識別化，但要保留結構、比例與金額。
